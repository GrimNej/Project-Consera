# Consera Demo Video Script

Target length: 4 minutes 50 seconds.  
Primary track: AI-Native Data Application.

## Recording setup

- Record the browser at 1440 by 900 and export at 1080p.
- Use a clean profile with bookmarks, extensions, notifications, and personal data hidden.
- Use the single active AI Change Observatory project and one real published dossier.
- Start with sleeping warehouses, then open the workspace 60 seconds before recording.
- Use one transparent cut while live ingestion and evaluation finish.
- Show a real received email only after verifying it contains no private address or identifier.
- Never show Snowflake account locators, usernames, keys, session IDs, query IDs, or raw prompts.

## 0:00 to 0:20 | The hook

**Show**

The Consera landing hero. Let the signal-flow animation move once, then point to `Open Consera`.

**Say**

> Technology changes faster than product strategy. Most feeds tell teams what happened, but they do
> not tell them whether it changes their product. Consera learns the project, filters the noise, and
> interrupts only when evidence justifies action.

**On-screen caption**

`AI-native project intelligence | Built on Snowflake`

## 0:20 to 0:42 | Define the product

**Show**

Scroll only far enough to reveal the three-stage product story and architecture preview. Select
`Open Consera`.

**Say**

> This is a complete Snowflake-native project intelligence system. It turns reviewed project context
> and live public signals into cited consequence dossiers, deterministic alert decisions, email, and
> project-scoped answers.

## 0:42 to 1:25 | Show the reviewed project context

**Show**

Open Projects and select `AI Change Observatory`. Point to the active profile version, summary,
providers, dependencies, monitored topics, and constraints. Briefly show the evidence-backed review
model in the architecture flow.

**Say**

> Consera began with an ordinary Markdown brief, not a special schema. It screened that text as
> untrusted data, used Snowflake Cortex to propose a structured profile, and required human review
> before activation. This approved version tells the system to watch material changes across AI
> models, APIs, agents, inference, tooling, security, policy, licensing, and pricing.

## 1:25 to 1:52 | Prove silence first

**Show**

Open Overview. Point to signals reviewed, quietly dismissed, published consequences, alerts, and the
daily AI budget.

**Say**

> The objective is not maximum AI output. It is useful silence. Deterministic gates reject weak
> relevance before expensive analysis, and the product exposes both what earned attention and what
> stayed quiet. The same screen makes the AI budget visible.

## 1:52 to 2:27 | Run the real workflow

**Show**

Open Intelligence and select `Check for new signals`. Hold briefly on `Run queued`. Cut to the
completed run and toggle `Show dismissed`.

Overlay the repository flow SVG for six seconds:

`Hacker News API -> GitHub Actions bridge -> Snowflake landing -> task graph -> Cortex -> policy -> email`

**Say**

> The daily run is automatic, and this button provides an on-demand proof. One bounded GitHub
> Actions bridge reads the official Hacker News API and lands one idempotent batch in Snowflake.
> Streams and triggered Tasks normalize it, compare it with active projects, select evidence, and
> invoke Cortex only for plausible candidates. Most items stop here, quietly and cheaply.

## 2:27 to 3:13 | Show one consequence dossier

**Show**

Open the strongest published dossier. Point in order to the project, headline, relevance, impact,
confidence, explanation, suggested actions, protective factors, score contribution, evidence links,
and uncertainty.

**Say**

> This signal cleared the relevance gate for this specific project. Cortex explains the possible
> consequence, but it cannot publish by itself. Consera validates the schema and citations, then
> deterministic scoring decides whether the dossier is visible. The result states what may change,
> what protects the project, what to do next, and where every external claim came from. Uncertainty
> remains explicit.

## 3:13 to 3:39 | Turn intelligence into action

**Show**

Open Alerts. Toggle `Sent` and `Suppressed`. Point to the 72-hour dedupe and three-per-day ceiling.
If a qualifying email has been received, show the sanitized message for three seconds.

**Say**

> Consera acts only after policy. A qualifying dossier sends an evidence-linked email. Low
> relevance, cooldown, duplicates, and daily limits create auditable suppression records instead.
> Silence is a recorded decision, not a missing result.

## 3:39 to 4:10 | Ask a cited question

**Show**

Open Ask Consera, select the active project, and submit:

```text
What should this project investigate first, and what protects it from replacement pressure?
```

Point to the answer, confidence, suggested action, and supporting evidence.

**Say**

> Natural language is the final interaction layer, not a disconnected chatbot. Retrieval is scoped
> to the approved project and stored evidence. The answer is cited, confidence is visible, and the
> recommendation traces back to the same intelligence record.

## 4:10 to 4:36 | Prove the implementation

**Show**

Use fast, readable cuts:

1. The README architecture SVG.
2. A sanitized Snowflake task graph or object list.
3. Snowpark procedure and deterministic policy filenames.
4. One successful sanitized Cortex Code review artifact.
5. The zero-warning test summary and cost guard.

Keep code text visible for no more than two seconds per cut.

**Say**

> Snowflake owns the system of record, versioned profiles, evidence, work queues, model usage,
> verdicts, and alerts. Snowpark Python performs the pipeline. Streams and triggered Tasks move work
> safely. Cortex returns bounded structured analysis. Secure views and allowlisted procedures serve
> the product through key-pair authentication. Cortex Code helped review the Snowflake
> implementation, and the repository includes deterministic, accessibility, security, and cost
> gates.

## 4:36 to 4:50 | Close on the value

**Show**

Return to the dossier, then fade to the Consera logo and URL.

**Say**

> Consera is not a news reader. It is an evidence-bound intelligence system that learns what a team
> is building, detects what actually matters, explains the consequence, and earns the right to
> interrupt. Consera: hear only what changes the plan.

**On-screen caption**

`consera.grimnej.com`

## Editing rules

- Use product audio or a restrained ambient bed below the voice, never both at equal volume.
- Add captions and verify every technical term manually.
- Use subtle cursor emphasis, not aggressive zooms or transition packs.
- Keep the product at normal speed. Speed up only waiting footage, with an explicit time-cut label.
- Do not imply that every ingestion run creates a verdict or email.
- Do not call fixtures live, fabricate a signal, or show an email that was not received.
- Let the product occupy at least 80 percent of the runtime.

## Backup for finalist judging

Prepare the same route as a live five-minute demonstration. Keep the submitted video, sanitized
screenshots, and architecture SVG immediately available if an external API is temporarily
unavailable. A backup explains an outage; it must never be presented as a successful live run.
